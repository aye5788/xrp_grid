# Phase 1 — Standalone Balthasar (risk agent)

Rebuild of the MAGI **Balthasar** survival/risk agent as a standalone
Anthropic-Console agent, decoupled from Letta. This is Phase 1 of migrating the
council off the Letta runtime (see `01_CURRENT_STATE.md` — Session 2026-05-28
SHUTDOWN). The authoritative baseline for current behaviour is the shutdown
snapshot at `snapshots/letta_shutdown_2026-05-28/`.

## Contents

- `balthasar_schema.py` — `BalthasarR0` Pydantic model (`extra="forbid"`); the
  enforced output shape: `position`, `geometry_veto`, `conviction`,
  `key_evidence`, `crux`.
- `balthasar_persona.md` — system prompt. Started from the shutdown-snapshot
  persona (`config/prompts/balthasar_prompt.txt`, byte-identical to disk), with
  only these corrections vs. the stale snapshot text:
  - fees → maker 0.25% / taker 0.40%, round-trip break-even maker-maker ~0.50%;
  - mode → LIVE since 2026-05-23 (removed all "PAPER mode" language);
  - R1 → conditional / novelty-gated since 2026-05-27 (removed "R1 always fires");
  - the Letta `BEGIN/END_AUTOGENERATED_SIGNALS` machinery → a plain inline list
    of the Balthasar-consumer `world_state` fields.
  The decision tree, the stranded-grid carve-out (geometry_veto + R1), and the
  Step 0.5 open-round-trip hold gate are preserved verbatim.
- `scenarios/dataset.jsonl` — copy of `evals/balthasar/dataset.jsonl` (9
  samples). Samples whose ground truth depends on a **retired** rule carry a
  `_drift_flag` string and are skipped by the runner:
  - **id 4, id 5** — depend on the removed STEP 1.4/1.5 `order_count_skew`
    ±0.7/±0.3 bands; under the current persona both resolve to CLEAR, so the
    stored ground truth is no longer derivable.
  - **id 9** — cites the retired `order_count_skew<0.7` band in its rationale,
    but its CLEAR ground truth is still derivable via Step 5; flagged for the
    stale citation only.
  Graded (non-flagged) samples: ids 1, 2, 3, 6, 7, 8.
- `balthasar_runner.py` — headless runner.
- `results/` — timestamped run outputs (`run_<UTC>.json`).

## Running

```bash
export ANTHROPIC_API_KEY=sk-ant-...
export BALTHASAR_MODEL=claude-haiku-4-5   # optional; this is the default
python phase1_balthasar/balthasar_runner.py
```

The runner loads the persona as the system prompt, replays each non-flagged
scenario through the Anthropic Messages API with output forced to the
`BalthasarR0` schema (single forced tool), grades, and writes
`results/run_<timestamp>.json`. The aggregate accuracy prints to stdout.

## Env vars

- `ANTHROPIC_API_KEY` — required (read by the `anthropic` SDK directly).
- `BALTHASAR_MODEL` — model handle; defaults to `claude-haiku-4-5` (production
  ran Balthasar on Haiku). Override to test other tiers; not hardcoded in logic.

## Grading & pass threshold

- `position` — exact match (always graded).
- `geometry_veto` — exact match, only when a sample carries ground-truth
  geometry_veto (this dataset does not; path wired for future datasets).
- `conviction` — within ±0.2, only when present.
- `crux` — not auto-graded.

A sample passes iff every graded field passes. **Pass threshold: ≥ 0.70
accuracy** on non-flagged samples, matching the existing
`evals/balthasar/suite.yaml` gate.
