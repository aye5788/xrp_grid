# Tuning Casper's persona instruction with `adk optimize`

Eval-guided rewrite of `magi/agents/personas/casper.md`. The optimizer runs the
**stateless RegimeVote agent** (`agent.py`, native `gemini-2.5-flash`) over the
Casper regression cases, scores `position` against ground truth
(`metrics.py`), and proposes an improved instruction. **It rewrites only the
instruction string — never the schema, the model, or the other two agents.**

## Billing (read first)

- Casper's candidate model AND the default optimizer model are both Gemini, so
  this run is **100% Gemini API** — no OpenAI/Anthropic spend.
- Runs on the **free `GOOGLE_API_KEY`** already in `.env`. Do NOT switch to a
  Vertex/Cloud key to "save money": Vertex bills per-token from request one and
  has no free tier (per-token price ≈ paid Gemini API). The free tier's only
  limit is **rate** (low req/min + a daily cap), not dollars.
- Keep `max_metric_calls` small so the run fits the free-tier rate limits.
  `agent.py` adds 429 retry-backoff to survive transient throttling.
- Free-tier note: Google may use free-tier prompts/responses for product
  improvement. Persona + world_state aren't secret, but be aware.

## Run sequence (from repo root)

```bash
cd /root/xrp_grid
source optimize/.venv/bin/activate

# 1. Snapshot the current persona before anything can overwrite it.
cp magi/agents/personas/casper.md /tmp/casper_2026-06-01.md

# 2. Build the ADK evalset from the existing Casper regression dataset.
python optimize/casper/build_evalset.py     # -> optimize/casper/train_eval_set.evalset.json

# 3. SMOKE run — cheapest possible, validates the whole pipeline for ~12-15 calls.
echo '{"max_metric_calls": 10}' > /tmp/opt_smoke.json
adk optimize optimize/casper \
  --sampler_config_file_path   optimize/casper/sampler_config.json \
  --optimizer_config_file_path /tmp/opt_smoke.json \
  --print_detailed_results

# 4. Real free-tier run once the smoke run prints a sane optimized instruction.
adk optimize optimize/casper \
  --sampler_config_file_path   optimize/casper/sampler_config.json \
  --optimizer_config_file_path optimize/casper/optimizer_config.freetier.json \
  --print_detailed_results
```

## After the run — DO NOT auto-apply

`adk optimize` prints the optimized instruction; it does not ship it. Before
adopting it:

1. **Diff** the proposed instruction against `casper.md`. Read it.
2. **Confirm the auto-generated SIGNALS block survived** — `casper.md` has a
   schema-driven region between `<!-- BEGIN_AUTOGENERATED_SIGNALS -->` and
   `<!-- END_AUTOGENERATED_SIGNALS -->` that `provision_agents.py` owns. If the
   optimizer rewrote inside those markers, discard that part; the schema is the
   source of truth there.
3. **Regression-gate it**: paste the new instruction into `casper.md` (outside
   the markers), then run the existing persona regression before trusting it —
   the optimizer maximizes this same signal, so confirm it didn't overfit the 8
   cases. Snapshot is already in `/tmp/` if you need to revert.
4. Ship by hand-editing `casper.md`. No auto-overwrite, no commit (operator
   pushes).

## Smoke run — VERIFIED WORKING (2026-06-01)

Ran `adk optimize` at `max_metric_calls=10` (11 Gemini calls, free tier, $0,
exit 0). Result: current `casper.md` scores **0.875 (7/8)** on the regime cases;
the one miss is **casper_005 (ground truth UNCERTAIN)**. `best_idx=0` — at smoke
budget GEPA only had room for the seed eval + one 3-case reflection, so it kept
the seed (proposed instruction == casper.md byte-for-byte). A real attempt to
beat 7/8 needs the bigger budget (`optimizer_config.freetier.json`,
max_metric_calls=20), still free-tier.

Three real issues were found and fixed to get here (all baked into `agent.py`):

1. **LIVE-COUNCIL BUG (not just tooling) — FIXED 2026-06-01:** Casper's
   native-Gemini call 400s on `RegimeVote`'s `additionalProperties: false` (from
   `extra="forbid"`). The live `magi/agents/schemas.py:RegimeVote` was relaxed to
   `extra="ignore"` (GridVote/RiskVote stay strict — they go via LiteLlm to
   OpenAI/Anthropic). `agent.py` now uses `RegimeVote` directly (the temporary
   `RegimeVoteGemini` subclass was removed). Not re-tested via a live cycle.
2. **ADK gap:** `adk optimize` does not register `EvalConfig.custom_metrics` into
   the metric registry (only `adk eval` does) → `agent.py` registers
   `regime_position_match` at import.
3. **sys.path:** `adk optimize` doesn't leave `optimize/` on `sys.path`, so the
   metric's dotted path wouldn't import mid-run → `agent.py` inserts it.

The `criteria` value shape `{"threshold": 0.75}` and the metric path
`casper.metrics.regime_position_match` are both confirmed working as written.
